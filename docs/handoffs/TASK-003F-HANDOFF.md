## 2. Breaking Changes Migrated

1. `next lint` was removed in Next.js 16. The `lint` script now runs
   `eslint . --max-warnings=0` with `eslint.config.mjs` flat config.
2. A separate `typecheck` script runs `tsc --noEmit`; Docker executes lint,
   typecheck, then build so Next.js 16's build no longer hides lint omissions.
3. Server `params` and `searchParams` are typed as promises and awaited before use.
4. Client dynamic pages read route IDs through `useParams`; they no longer use
   the removed synchronous page-prop contract.
5. `cookies()` is awaited before constructing the server-only NextAuth request.
6. React moved to 19.2.8 with matching type definitions.
7. Next-generated TypeScript requirements are retained: `jsx: react-jsx`,
   `target: ES2017`, and `.next/dev/types/**/*.ts` inclusion.
8. Portal `<html>` declares `data-scroll-behavior="smooth"`, preserving the
   intended Next route transition behavior for its global smooth scrolling.
9. Internal auth navigation uses Next `Link`, satisfying the Next 16 lint rules.
10. Next.js 16 uses Turbopack by default for production builds; no webpack bypass
    or custom alias was needed.
11. Removed the recursive NextAuth `pages.signIn = "/api/auth/signin"`
    override from both apps. The override pointed the API sign-in endpoint to
    itself and caused an infinite 302 loop; the standard provider page is now
    used without weakening Keycloak authentication.

## 3. ESLint Compatibility Decision

ESLint 10.8.1 satisfies the broad peer range but failed at runtime with the
TypeScript parser stack shipped through the current Next config
(`scopeManager.addGlobals is not a function`). Therefore ESLint is pinned to
the latest compatible 9.x line, `9.39.5`. Do not upgrade ESLint to 10 based only
on peer metadata; require a clean lint execution in both apps first.

## 4. Reproducible Lockfile Rule

The initial lockfiles generated by a newer host npm omitted optional native
package metadata and failed `npm ci` inside Node 22/npm 10 Docker images. Final
lockfiles were regenerated using npm `10.9.8`, matching the Docker image.

Mandatory command after dependency changes:

```powershell
npx.cmd --yes npm@10.9.8 install --package-lock-only --ignore-scripts
```

Then prove reproducibility with a no-cache Docker build. A local `npm install`
or cached build alone is not sufficient evidence.

## 7. Strict Rules for Future Agents/Gemini

1. Read this handoff before changing frontend dependencies or request APIs.
2. Keep Portal/Admin framework versions exact and identical.
3. Never restore `next lint`; it does not exist in Next.js 16.
4. Never use synchronous `params`, `searchParams`, `cookies`, `headers`, or
   `draftMode` in Next server code.
5. Do not add `--webpack` merely to silence Turbopack failures; diagnose the
   incompatibility and document any approved fallback.
6. Do not accept a lockfile until clean Docker `npm ci` passes.
7. Do not upgrade ESLint 9 to 10 without executing both flat configs.
8. Do not downgrade Next.js to suppress a regression or security finding.
9. Do not modify vendor UI originals as part of framework maintenance.
10. Do not run force audit fixes; inspect the proposed dependency graph and
    obtain approval for any new major version.

## 8. Rollback

Rollback is Git-based: revert the TASK-003F commit and rebuild both images from
the prior lockfiles. No database, Keycloak, Moodle, volume, or API schema change
is part of this upgrade. Do not reset Docker volumes during frontend rollback.
